# Dev Plugin

開発ワークフローを支援する Claude Code plugin です。

## 機能

### Skills

| スキル             | 説明                                                                          |
| ------------------ | ----------------------------------------------------------------------------- |
| `/dev:comment`     | 変更差分を分析し、実装意図 (Why) を説明するコメントを追加                     |
| `/dev:do`          | 複数タスクを並列実行 (subagent / Agent Teams 自動選択)                        |
| `/dev:plan`        | 資料を分析してフェーズ別行動計画を作成                                        |
| `/dev:docs-html`   | 引数の内容を用途別カテゴリに分類し、dark/light + 日/英 切替付き HTML を生成   |
| `/dev:feedback`    | フィードバック/レビューの妥当性を検証し、現在のコンテキストに沿う指摘のみ修正 |
| `/dev:review`      | ローカル変更を複数 AI でレビューし、指摘箇所を自動修正                        |
| `/dev:orchestrate` | 大モデルが計画・統合、小モデル worker が実行する orchestrator-workers 実行    |
| `/dev:advise`      | 判断ポイントで強いモデルの advisor に相談してセカンドオピニオンを取得         |

### Agents

| エージェント  | モデル | 説明                                                                     |
| ------------- | ------ | ------------------------------------------------------------------------ |
| `dev:worker`  | sonnet | orchestrate から起動される実行役。蒸留された結果のみを報告               |
| `dev:advisor` | fable  | advise から起動される相談役。診断・推奨・代替案・リスクを返す (助言のみ) |

## インストール

### マーケットプレースから (推奨)

```bash
# 1. マーケットプレースを追加
/plugin marketplace add ronnnnn/cc

# 2. プラグインマネージャーを開く
/plugin

# 3. Discover タブで "dev" を選択してインストール
```

または CLI から直接インストール:

```bash
/plugin install dev@cc
```

**インストールスコープ:**

| スコープ  | 説明                                   |
| --------- | -------------------------------------- |
| `user`    | 全プロジェクトで使用可能 (デフォルト)  |
| `project` | このリポジトリの全コラボレーターで共有 |
| `local`   | このリポジトリで自分のみ使用           |

スコープを指定してインストール:

```bash
claude plugin install dev@cc --scope project
```

## 使い方

### コメント追加

```bash
/dev:comment  # ローカルの変更差分にコメントを追加
```

自然言語でも起動します:

```
コメントを追加して
変更にコメントを付けて
実装意図をコメントして
add why comments
```

**ワークフロー:**

1. `git diff HEAD` で staged + unstaged の変更差分を取得
2. 各変更ファイルを読み込み、既存コメントの言語・スタイルを確認
3. 「なぜそうしているのか (Why)」が必要な箇所を特定
4. 実装意図が不明な場合はユーザーに確認
5. Edit ツールでコメントを直接追加

**特徴:**

- **Why のみコメント** - コードを読めばわかる What コメントは追加しない
- **既存スタイル準拠** - ファイル内の既存コメントの言語と形式に合わせる
- **13 言語対応** - TypeScript, Python, Go, Rust, Dart, Swift, Kotlin/Java 等のコメント形式テーブルを内蔵
- **意図不明時は確認** - 推測でコメントを書かず、AskUserQuestion で実装者に確認

### 並列タスク実行

```bash
/dev:do タスク1、タスク2、タスク3
```

自然言語でも起動します:

```
並列でやって
同時に作業して
これとこれとこれをやって
```

**ワークフロー:**

1. 引数からタスクを抽出・分類
2. subagent / Agent Teams を自動選択
3. 並列実行
4. 結果を集約して報告

### 行動計画作成

```bash
/dev:plan <資料パス or URL>
```

自然言語でも起動します:

```
行動計画を作成して
アクションプランを作成
資料から計画を立てて
```

**ワークフロー:**

1. 資料 (ファイル、URL、PR、設計書等) を読み込み・分析
2. 不明点をインタビューで明確化
3. アトミックなタスクに分解
4. 依存関係を整理してフェーズ構成
5. フェーズごとにファイルを分割して出力

### HTML ドキュメント生成

```bash
/dev:docs-html <内容、資料パス、URL、PR など>
```

自然言語でも起動します:

```
HTML ドキュメントを作って
HTML 資料を生成して
リッチな資料を HTML で出力して
```

**特徴:**

- **カテゴリ自動分類** - 内容に応じて `plan` / `review` / `design` / `prototype` / `report` / `explainer` / `diagram` / `slide` / `editor` から最適なレイアウトを選択
- **dark/light モード切替** - すべての生成 HTML に組み込み、`prefers-color-scheme` を初期値に `localStorage` で永続化
- **日/英 言語切替** - 全テキストを両言語で保持し、ボタン操作で瞬時に切替 (ページ再ロード不要)
- **単一ファイル・外部依存なし** - CSS/JS/SVG をすべて 1 ファイルに内包しブラウザでそのまま開ける
- **モバイル対応** - レスポンシブ設計とアクセシビリティ (ARIA, focus) を確保

**ワークフロー:**

1. 引数 (ファイル/URL/PR/テキスト) を読み込み・分析
2. カテゴリを判定 (不明確な場合は AskUserQuestion で確認)
3. 出力先パスを確認
4. 日/英 両言語のコンテンツを準備
5. ベーステンプレートにカテゴリ別レイアウトを適用して HTML を生成
6. セルフチェック (テーマ/言語切替、レスポンシブ) を実行

### フィードバック検証・反映

```bash
/dev:feedback <フィードバックやレビューの内容>
```

自然言語でも起動します:

```
このレビューに対応して
フィードバックを反映して
指摘内容を検証して
レビューコメントを取り込んで
```

**特徴:**

- **妥当性を検証** - 指摘を鵜呑みにせず、実際のコードと差分を確認し事実誤認・論理矛盾・既対応がないか吟味
- **現在のコンテキスト基準** - 修正の要否をセッションの方針とブランチ差分に照らして判断
- **スコープ外・方針違いは見送り** - 妥当な指摘でも今回の範囲外・方針と異なるなら修正せず理由付きで報告
- **修正は即実施** - 修正対象と判定した指摘はそのまま反映し、判定結果と対応をまとめて報告

**現在のコンテキスト:**

| 状況                   | 差分の取得方法                         |
| ---------------------- | -------------------------------------- |
| デフォルトブランチ以外 | 分岐元 (merge-base) から現在までの差分 |
| デフォルトブランチ     | staged + unstaged の差分               |

加えて、セッション中に確立した目的・設計判断・方針も判定基準に含めます。

**ワークフロー:**

1. 引数 (なければ確認) を個別の指摘単位に分割
2. セッション方針とブランチ差分で現在のコンテキストを収集
3. 各指摘を妥当性・スコープ・方針整合性で判定して分類
4. 判断が不明瞭な指摘は AskUserQuestion で確認
5. 修正対象と判定した指摘を即反映
6. 判定結果 (修正/見送り) と理由をまとめて報告

### ローカルレビュー

```bash
/dev:review  # ローカルの変更 (staged/unstaged) をレビュー
```

自然言語でも起動します:

```
ローカル変更をレビューして
コミット前にセルフレビューして
変更をレビューして直して
```

**特徴:**

- **複数 AI で並列レビュー** - Claude / Codex (codex-plugin-cc コマンド優先・MCP フォールバック) / Antigravity MCP を同時利用
- **承認なしで自動修正** - 修正が必要な指摘を自動で反映
- **指摘がなくなるまで反復** - レビューと修正を最大 3 回繰り返す
- **規模に応じてアプローチ自動選択** - 単一 subagent / Agent Teams を変更量・複雑度で切替

**ワークフロー:**

1. ローカル差分を取得 (staged + unstaged)
2. 変更量・環境に応じて subagent / Agent Teams を選択
3. 複数 AI で並列レビューし、結果を統合・重複排除
4. 修正が必要なものを承認なしで自動修正
5. 指摘がなくなるまでレビュー・修正を繰り返す (最大 3 回)
6. 修正サマリと残課題を報告

### Orchestrator-Workers 実行

```bash
/dev:orchestrate <達成したいゴール>
```

自然言語でも起動します:

```
オーケストレーションして
worker にファンアウトして
計画は大きく実行は小さく
コンテキストを汚さずに調査して
```

**特徴:**

- **plan big, execute small** - 計画・判断・統合はメインセッション (大モデル)、トークン集約的な実行は `dev:worker` (sonnet) が担当
- **コンテキスト保護** - ファイル精読やログ分析は worker のコンテキストで消化し、メインには蒸留された要点のみが返る
- **失敗の再割り当て** - 失敗したサブタスクは失敗内容を踏まえた改善ブリーフで再投入 (最大 2 回)
- **`dev:do` との使い分け** - do はユーザー列挙タスクの並列化、orchestrate は単一ゴールの分解とモデルコスト戦略

**ワークフロー:**

1. ゴール分析と軽量な偵察 (ファイル精読はしない)
2. 独立したサブタスクへ分解し、ウェーブ単位で計画
3. `dev:worker` へ単一メッセージで並列ファンアウト
4. 報告を監視し、失敗タスクを再割り当て
5. 全報告を統合して最終報告

### Advisor 相談

```bash
/dev:advise [相談内容]  # 省略時は現在のセッションの問題から自動構成
```

自然言語でも起動します:

```
アドバイスが欲しい
セカンドオピニオンをもらって
行き詰まったので相談したい
この方針で問題ないかチェックして
```

**特徴:**

- **強いモデルに相談** - `dev:advisor` (fable) がブリーフを検証し、診断・推奨・代替案・リスクを返す
- **独立した検証** - advisor はブリーフの主張を鵜呑みにせず、実際のコードを自身で確認して助言
- **多ターン相談** - SendMessage で同じ advisor にコンテキストを保持したまま追加相談が可能
- **盲従しない** - 助言が自身の証拠と矛盾する場合は矛盾点を明確にして判断

**ワークフロー:**

1. 相談内容を特定 (引数 or セッションコンテキスト)
2. 自己完結した相談ブリーフを構成 (ゴール・現状・試行履歴・制約・質問)
3. `dev:advisor` を起動して助言を取得
4. 証拠と照合して助言を適用
5. 必要なら SendMessage で追加相談
6. 適用結果と見送った助言を報告

> **Note:** Claude Code v2.1.98+ (Anthropic API) にはネイティブの advisor tool (`/advisor` コマンド) があり、会話全文を自動で advisor に渡せます。常時 advisor を使いたい場合はそちらを推奨します。このスキルは advisor tool が使えない環境や、相談のタイミングを明示的に制御したい場合の代替手段です。
